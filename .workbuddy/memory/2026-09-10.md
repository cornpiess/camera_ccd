## 代码 Review（用户报告「前置代码部分由 Gemini 编写」）

### 严重（已定位根因）
1. **三指校准手势与径向相机选择器互相抢占**（`App.tsx` L380-432 + `ThreeFingerGestureDetector.tsx` L38-65）。已通过读 RN 0.83 的 `PanResponder.js` 确认机理：`onStartShouldSetResponder` 在首指落下时必然只看到 1 个触点 → PanResponder 抢占成功并启动 350ms 长按计时器；此后第 2、3 指落下只会触发 `onResponderStart`，而代码**没有提供 `onPanResponderStart`**，所以 `onPanResponderGrant` 里的 `touches.length > 1` 守卫永远不会二次执行。结果：三指按住约 350ms 后径向轮盘会在校准 HUD 之上弹出。
   → 修复：给 `previewPanResponder` 增加 `onPanResponderStart`，当 `gestureState.numberActiveTouches > 1` 时取消长按计时器并关闭径向。
2. **RAW+Processed 双格式回调的错误守卫顺序颠倒**（`CameraEngineModule.swift` L442-450）。`guard error == nil … else { finish(.failure) }` 写在 `if expectedPhotoCount > 1 && !isRaw { return }` **之前**，导致伴生 processed 照片失败时会直接终结整次拍摄，即使 RAW 仍然正常。
3. **拍摄 Promise 存在永不结算的悬挂路径**（`CameraEngineModule.swift` L534-536）。若 `expectedPhotoCount == 2` 但只回调了 processed，processed 被忽略、`didFinishCaptureFor(error: nil)` 什么都不做 → Promise 永不 resolve → `isCapturing` 永久 true、快门永久禁用、delegate 永久滞留。缺超时兜底。

### 中等
4. **曲线点数契约不一致**：`validation.ts` L28 只要求 `curve.length >= 2` 且严格递增，Swift `ProfileRenderer.toneCurve` L736 要求**恰好 5 点**，否则静默丢弃整条曲线。8 个内置 Profile 都是 5 点所以暂时看不出来，但校准面板导入自定义 JSON 时会静默失效。
5. **临时文件清理会删掉正在显示的缩略图**：`CameraTempFiles.removeOlderFiles()`（L413-418）在每次按快门时连 `kept`（上一张的 file+thumb）一起删除，而 JS 侧 `latestThumbnail` 正指向它。新拍摄若失败，左下角缩略图永久破裂。
6. **实时预览遮罩几乎不可见，且丢失了风格主体**：实测（复算脚本）曝光层 0-4.5%、色温层 0.8-14.4%、色调层 0.7-6.7%；而 `tone.contrast`、5 点曲线、`color.saturation`、7 段 hueBands **完全没有预览映射**——这些恰是区分 Leica / Fuji 的主要因素。切相机时取景器几乎不变，与「实时看到胶片风格」的产品承诺不符。

## 无真机时的界面预览方案（用户提出「我手上没有真机 iPhone，想看看界面」）

### 关键事实（决定了方案形态）
- `src/camera/CameraEngine.tsx` 在**模块顶层**执行 `requireNativeModule('CameraEngine')` + `requireNativeViewManager('CameraEngine')`。
- `modules/camera-engine/expo-module.config.json` 声明 `"platforms": ["apple"]`，模块只有 `ios/`，无 Android 实现。
- `app.json` 原本只有 `"platforms": ["ios"]`；未装 `react-native-web` / `react-dom`。
- ⇒ **web / Android / Expo Go 全部在 import 阶段即崩**，不是「看不到摄像头」，而是整个 App 起不来。任何非 iOS 预览都必须先加一层假的原生模块。

### 采用的方案（bundle 层已验证通过；用户最终选择全部回滚，见文末）
用 Metro 平台后缀做零侵入替换：新增 `src/camera/CameraEngine.web.tsx`，iOS 真实路径一字未改。
- `CameraEngineView` 渲染合成参考场景（7 段天空 + 4 段地面 + 树线 + 高光块 + 4 色块 + 6 级灰阶 + `WEB PREVIEW · MOCK SENSOR` 角标），切相机时由真实 `ProfileOverlay` 叠加风格。
- 能力值默认 `supportsVariableAperture: false`，与真机诚实桩一致（光圈锁 `Fixed ƒ/x`）；`?aperture=variable` 仅用于查看可变光圈 UI 分支。
- 防漂移：用 `import type` 从 `./CameraEngine`（类型导入编译期擦除，不会引入原生模块）拉原生类型，再用 `Exact<A,B>`（互相可赋值 + `keyof` 双向相等）断言 4 组类型一致。**注意**：只做互相可赋值会漏掉「多出的可选字段」，必须同时比 `keyof`。已用「故意加必填字段」自检该断言确实会报错。

### 推送受阻的网络诊断（重要，换机/换网络复现时看这段）
本机处于中国大陆网络环境，且 WorkBuddy 沙箱注入了本地代理（env `HTTP_PROXY`/`HTTPS_PROXY` = `http://127.0.0.1:49713`）。实测矩阵：

| 目标 | 走沙箱代理 | 直连（`--noproxy`，VPN 开） | 直连（VPN 关） |
|---|---|---|---|
| `registry.npmjs.org` | 200 | 200 | 200 |
| `api.github.com` | 200 | 200 | 200 |
| `raw.githubusercontent.com` | 301 | — | — |
| `codeload.github.com` | 301 | — | — |
| **`github.com`** | **502** | **200/403（真实响应）** | **超时不可达** |

结论：
1. **只有 `github.com` 主域被阻断**（SNI 特征），其余 GitHub 子域正常。
2. 沙箱代理对 `github.com` **恒定返回 502**，与 VPN 开关无关——**推送必须绕开它**（`env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy git push`）。
3. 绕开后仍需 **VPN 开启**，否则 `github.com:443` 直接被墙。
4. TCP 实测：`github.com:443` 不可达，**`ssh.github.com:443` 可达**。但 `~/.ssh` 里没有任何密钥（只有空 `known_hosts`），且新增 SSH key 需要访问 github.com 网页端——绕不开 VPN。故 SSH 路线暂不可用。
